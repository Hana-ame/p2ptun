# p2ptun 弱网与高丢包传输基准测试报告 (Benchmark)

本文档记录了 `p2ptun` 在不同网络损伤（时延 RTT + 随机丢包率）条件下的端到端真实吞吐量基准测试，对比 **Hysteria 2 (Brutal CC: 100 Mbps)** 与 **Native QUIC (标准拥塞控制)** 的实际传输表现。

---

## 1. 测试方法与仿真模型

为完全复现公网跨国长途链路、4G/5G 弱信号、高峰期网络拥塞场景，我们在 UDP 传输层封装了双向管道损伤模拟器 (`lossyDelayedPacketConn`)：
- **时延仿真 (Latency)**：数据包送入 FIFO 交付队列，按单向 $RTT / 2$ 精确延时唤醒发送。
- **丢包仿真 (Packet Loss)**：服从均匀分布的伪随机丢包发生器，双向独立计算丢包概率。
- **数据完整性校验**：所有测试数据均执行 100% 逐字节校验与数据一致性比对。

## 3. 核心机制与原理对比

### 为什么标准 QUIC / TCP 在丢包网络下出现断崖式暴跌？
传统的拥塞控制算法（如 Cubic、NewReno 乃至 BBR）将数据包丢失作为**网络拥塞的核心信号**：
1. **窗口腰斩**：一旦发生丢包，发送方立即将拥塞窗口（`cwnd`）砍半或退避。
2. **长 RTT 恶性循环**：在 100ms~160ms 的高时延下，窗口每次恢复需要经历漫长的往返周期，丢包率一旦超过 5%，发送窗口几乎始终被压制在 1~2 个 MSS，导致吞吐率坍塌至数十甚至数千字节每秒（本测试中跌至 0.12 Mbps，1MB 耗时长达 70 秒）。

### 为什么 Hysteria 2 Brutal 算法能保持数十倍吞吐？
1. **速率驱动（Rate-Based Pacing）**：
   Brutal 拥塞控制由用户通过 `-bandwidth` 参数指定期望带宽（如 100 Mbps），发送引擎直接按照目标速率进行精密步长发包，**不将随机丢包作为减速信号**。
2. **高速选择性重传 (SACK)**：
   接收端快速回告未收到报文片段，发送端仅在空闲间隙高速重发丢失的包，数据管道始终被完全填满。
3. **适用于物理信道丢包**：
   在无线 Wi-Fi 干扰、4G/5G 移动切换以及国际跨网线路中，大多数丢包源于随机信道衰落而非路由排队溢出，Brutal 算法正是为此类场景量身定制。
